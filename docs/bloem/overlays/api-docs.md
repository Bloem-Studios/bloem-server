# Bloem overlay: Interactive API documentation

This overlay covers Silo's [`docs/api-docs.md`](../../api-docs.md), which stays exactly as Silo wrote it.

Silo's server has a built-in page for browsing its API, the **Swagger viewer** at
`/api/v2/docs`. Bloem serves the same viewer, unchanged. Bloem also has an API of
its own, under `/api/bloem/v2`, for the features Silo does not have, such as
organizations, plans and Live TV. The viewer does not show that second API.

## What Bloem changes

- **The viewer shows Silo's API only.** Signing in or picking a profile does not
  add Bloem's routes to it.
- **Bloem's API is described in a file in this repository.** To browse it, open
  that file in a Swagger viewer on your own computer. The server does not serve it.
- **Other places describe Bloem's API too:** the API catalogue, the API pages by
  topic and the native wire reference.

## For developers

### Section by section

---

**Location:** section “Interactive API documentation”. **Bloem adds:**

The bundled viewer at `/api/v2/docs` loads **only** the Silo native v2 contract
from `/api/v2/openapi.json`. It does not switch to Bloem extensions when a token
or a profile header is entered. Use its local Swagger UI assets for v2; no
internet-hosted validator is required.

Bloem's separate `/api/bloem/v2` contract is committed at
[`contracts/api/bloem/v2/openapi.json`](../../../contracts/api/bloem/v2/openapi.json).
This artifact is not served at an assumed `/api/bloem/v2/openapi.json` or
`/api/bloem/v2/docs` route. To browse it with Swagger tooling, load the committed
file into a trusted local viewer. Set that viewer's server/base URL explicitly
when executing requests; native administrative writes require the appropriate
organization/platform context, not just a normal account login.

The [API catalogue](../api-catalogue.md) lists typed operations and documentation
gaps, and the [API by topic](../api/README.md) pages are generated from the same
artifact. The [native wire reference](../../bloem-api-reference.md) describes
organization, household, Live TV and chi-handler wire conventions. The generated
native artifact covers the explicit inventory operations; production mount tests
check method-level agreement for conditional groups. These sources complement
each other; the v2 viewer does not certify native route coverage.

Experimental [native-storage administration](../../bloem-api-reference.md#native-storage-administration)
is also Bloem-only: its platform/organization routes and protected capability
schema are included in the [native OpenAPI artifact](../../../contracts/api/bloem/v2/openapi.json),
separate from the Silo OpenAPI surface. The composed
server can support authorized EPUB/PDF onboarding while keeping
`backend_verified: false`; generated DTO presence and artifact approval do not
certify a provider or establish native-client adoption.

Use the generated artifacts from the source you are building. Documentation does not
establish a server's running revision, provider readiness or native-client
adoption.
